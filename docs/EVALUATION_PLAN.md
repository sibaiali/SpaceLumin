## Proposed Evaluation System

### A. Prediction Accuracy (Markov Chain)

**Ground truth definition:**
- A prediction of `collisionRisk > 0.7` is CORRECT if the player enters a dense zone (≥6 enemies) within the next 1-3 seconds
- A prediction of `panicRisk > 0.7` is CORRECT if jerk > 800 within the next 1-3 seconds
- A prediction of `missedBurstRisk > 0.6` is CORRECT if next 5 shots contain ≥3 misses

**Metrics:**
```
accuracy = correct_predictions / total_predictions
precision = TP / (TP + FP)
recall = TP / (TP + FN)
F1 = 2 × precision × recall / (precision + recall)
```

**Test procedure:**
1. Enable prediction logging in PredictiveAI: `logPrediction(risk, threshold, actualOutcome)`
2. Run 30+ gameplay sessions (15 min each)
3. Export to CSV: timestamp, predicted_risk_type, confidence, actual_outcome, lag_seconds
4. Compute metrics per risk type, per session

### B. Baseline Comparisons

| Baseline | Description |
|---|---|
| Random baseline | P(flag=1) = 0.5 for each risk — coin flip |
| Frequency baseline | Always predict the most common state transition (no markov) |
| Persistent baseline | Predict current state = next state (no change) |
| Current system | PredictiveAI Markov chain |

**Acceptance criterion:** System must beat all three baselines by ≥5 percentage points in F1 score to claim value.

**Required data fields:**

- `confidence` (0-1)
- `outcome` (boolean — did risk materialize within lag window?)
- `lagMs` (time from prediction to outcome)

### D. Latency Measurement

```javascript

// Expected: <0.1ms based on O(36) complexity
```

### E. Frame-Time Impact

Measure: `frame time WITH all AI systems` vs `frame time WITHOUT AI systems`

Expected impact: <0.5ms per frame based on complexity analysis.  
Target: <1ms total AI overhead at 60fps.

### F. Statistical Validity

**Minimum sample size:** 50 sessions × average 300 predictions/session = 15,000 predictions  
**Significance test:** McNemar's test (paired comparison of system vs. baseline)  
**Required p-value:** < 0.05

### G. Nystrom/KLR Evaluation

**Overload detection accuracy:**
- Ground truth: player behavior degradation (accuracy drop >20% in 5s window, repeated damage taken)
- System output: `overloadProb > 0.65`

**Stimulus attribution accuracy:**
- Ground truth: manually reduce one stimulus and observe system response
- Acceptance: system identifies the reduced stimulus as top attribution ≥70% of trials

## Using Existing Telemetry Data

The 1000+ JSONL files in `telemetry_factory/` are **synthetic** (generated by `headless_orchestrator.js`).  
They contain `profile` labels like "Perfect Flow", suggesting they represent scripted behavioral archetypes.

**What this data CAN evaluate:**
- Nystrom kernel fitting behavior
- Lasso attribution scores under different profiles
- KLR classification consistency

**What this data CANNOT evaluate:**
- Real prediction accuracy (synthetic data follows known profiles — no genuine uncertainty)
- Human player adaptation
- Genuine collisionRisk materialization

### Proposed Synthetic Evaluation Script

```javascript
// headless_accuracy_eval.js (PROPOSED — NOT YET WRITTEN)
// Read episode JSONL files, replay tick-by-tick,
// compare predictions at tick T vs actual outcomes at tick T+N

const episodes = loadEpisodes('telemetry_factory/');
for (const ep of episodes) {
    predictiveAI.reset();
    for (let i = 0; i < ep.ticks.length; i++) {
        const tick = ep.ticks[i];
        predictiveAI.recordEvent('position', tick.kinematics);
        if (i > 20) {
            const pred = predictiveAI.predict();
            const future = ep.ticks[i + 20]; // 1-second lookahead
            evaluator.logPair(pred, future);
        }
    }
}
evaluator.report();
```
